# DiscoCV

[English](README.md) | **Українська**

Інтерактивне резюме-портфоліо у 3D-диско-кімнаті. Дзеркальна куля кидає світло на стіни, програвач і колонка реагують на музику, а сама сторінка — повноцінне резюме: досвід, проєкти, навички та PDF для завантаження трьома мовами.

**Сайт:** https://konradiuss.github.io/MyDiscoCV/

![Головний екран з диско-кулею](.github/readme/hero.jpg)

## Можливості

- **3D-диско-кімната** на Three.js: дзеркальна куля, що обертається, відблиски світла, які рухаються стінами, сяйво навколо кулі та сітка підлоги в перспективі кімнати.
- **Музичний плеєр** з кнопками відтворення, перезапуску та гучності — у кутку сторінки й на програвачі в кімнаті. Динаміки колонки та індикатор рівня реагують на трек через Web Audio API.
- **Платівки на підлозі**: кожна — окремий трек. Наведіть курсор, щоб підняти платівку, і натисніть, щоб увімкнути.
- **Три мови**: українська, російська та англійська, кожна зі своєю адресою (`/ua`, `/ru`, `/en`) і своїм PDF-резюме.
- **Таймлайн кар'єри**: поточна робота підсвічена, перерви між роботами приглушені, тривалість рахується з дат.
- **Скриншоти проєктів** у переглядачі з підтримкою клавіатури.
- **Односторінкові PDF-резюме**, згенеровані з тих самих даних, що й сайт.
- **Адаптивна верстка** до 320px, підтримка `prefers-reduced-motion` і стилі для друку.
- **Доступні елементи керування**: кожен елемент керування в 3D-сцені — справжня HTML-кнопка чи повзунок з підписом і підтримкою клавіатури.
- **Без бекенду**: статичний сайт, розгорнутий на GitHub Pages.

## Технології

- [Vue 3](https://vuejs.org/) з `<script setup>` і TypeScript
- [Vite](https://vite.dev/) та [Vue Router](https://router.vuejs.org/)
- [Three.js](https://threejs.org/) з власними GLSL-шейдерами
- [Vitest](https://vitest.dev/) і Vue Test Utils для модульних тестів
- [Playwright](https://playwright.dev/) для end-to-end тестів і генерації PDF
- ESLint, Oxlint і Prettier

## Структура проєкту

```text
src/
├── data/
│   ├── resume.ts        # увесь вміст резюме, окремий блок для кожної мови
│   └── playlist.ts      # музичний плейлист
├── assets/
│   ├── audio/           # музичні треки
│   ├── covers/          # обкладинки альбомів для платівок
│   ├── avatars/         # фото профілів для плиток контактів
│   ├── shots-source/    # скриншоти проєктів такими, якими їх зняли
│   ├── shots/           # WebP, які віддає сайт, зібрані з shots-source/
│   ├── documents/       # згенеровані PDF-резюме
│   └── main.css         # стилі сайту
├── components/
│   ├── DiscoRoomBackground.vue   # 3D-сцена
│   ├── disco/           # геометрія сцени, відблиски, шейдери, розкладка підлоги
│   ├── controls/        # керування музикою, семисегментні індикатори, прокрутка
│   └── resume/          # дати, таймлайн, стан переглядача скриншотів
├── audio/               # музичний плеєр та аналіз звуку
├── loading/             # екран завантаження
└── __tests__/           # модульні тести
e2e/                     # тести Playwright
scripts/
└── build-resume-pdf.ts  # генератор PDF-резюме
```

### Як змінити вміст

- **Текст резюме**: редагуйте `src/data/resume.ts`. Кожна мова записана повністю. Модульні тести перевіряють, що дати, стек, посилання та скриншоти збігаються в усіх трьох мовах.
- **Скриншоти**: покладіть оригінал у `src/assets/shots-source/`, запустіть `npm run shots:optimize` і вкажіть назву згенерованого `.webp` у `resume.ts`. Оригінали лишаються на місці, тож налаштування можна змінити й зібрати все заново, жодного разу не стискаючи вже стиснуте; у збірку потрапляє лише `src/assets/shots/`.
- **Музика**: покладіть трек у `src/assets/audio/`, обкладинку — у `src/assets/covers/` і додайте запис у `src/data/playlist.ts`.
- **PDF-резюме**: після зміни вмісту запустіть `npm run resume:pdf`.
- **Прев'ю посилань**: в `index.html` між маркерами `share-meta` лежать англійські теги, а збірка кладе їхню локалізовану копію в `/ua`, `/ru` та `/en` — див. `scripts/shareMeta.ts`. Опис підхоплює `profile.summary` сам, а от у картинку запечені ім'я, посада, місто й готовність до роботи, тож після зміни будь-чого з цих чотирьох запустіть `npm run share:image`.

## Запуск

Потрібен Node.js 22.18+ або 24.12+.

```sh
npm install
npm run dev
```

Після цього відкрийте http://localhost:5173.

### Скрипти

| Команда                  | Що робить                                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run dev`            | Запускає dev-сервер                                                                                                                                |
| `npm run build`          | Перевіряє типи та збирає продакшн-версію                                                                                                           |
| `npm run preview`        | Локально віддає продакшн-збірку                                                                                                                    |
| `npm run test:unit`      | Запускає модульні тести Vitest                                                                                                                     |
| `npm run test:e2e`       | Запускає end-to-end тести Playwright (спочатку виконайте `npx playwright install`)                                                                 |
| `npm run resume:pdf`     | Генерує PDF-резюме (`-- en` — лише одна мова, `-- --preview` — ще й PNG-прев'ю)                                                                    |
| `npm run shots:optimize` | Збирає скриншоти для сайту з `src/assets/shots-source/` (`-- --force` — перезібрати все, `-- --width`/`-- --quality` — інші налаштування)          |
| `npm run share:image`    | Знімає кімнату для прев'ю посилань (`-- en` — лише одна мова, `-- --skip-build` — узяти наявний `dist/`, `-- --motion` — дати сяйву поворухнутися) |
| `npm run icons:build`    | Збирає значки для домашнього екрана та `site.webmanifest` із `compact-disc.svg`                                                                    |
| `npm run scene:measure`  | Вимірює час кадру 3D-кімнати (`-- --desktop`, `-- --throttle 4`, `-- --experiments` — оцінити кожну частину окремо)                                |
| `npm run lint`           | Запускає Oxlint і ESLint                                                                                                                           |
| `npm run format`         | Форматує код за допомогою Prettier                                                                                                                 |

### Як виміряти кімнату

У 3D-сцені є два перемикачі для діагностики, обидва вимкнені, доки їх не попросять:

- `?fps` показує на сторінці невеликий лічильник часу кадру. Вимірювання в headless-браузері йде через процесор і не передбачає GPU телефона, тож правду каже саме цей лічильник — відкрийте сайт на самому телефоні й дивіться на `p95`, бо смикання — це саме він.
- `?quality=high` чи `?quality=low` примусово вмикає рівень якості замість автоматичного вибору, щоб порівняти їх поруч.

Рівень визначається в `src/components/disco/sceneQuality.ts` окремо від ширини екрана: ширина відповідає за кадрування, потужність пристрою — за вартість.

## Розгортання

Сайт розгортається на GitHub Pages за допомогою [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) після кожного push у `main`. Workflow запускає модульні тести, збирає сайт і публікує `dist/`.

Щоб розгорнути форк:

1. Відкрийте **Settings → Pages** у репозиторії та встановіть **Source**: **GitHub Actions**.
2. Зробіть push у `main` або запустіть workflow вручну на вкладці **Actions**.

Базовий шлях збірка бере зі змінної середовища `PAGES_BASE`, яку workflow встановлює в `/<назва-репозиторію>/`. GitHub Pages не має fallback для односторінкових застосунків, тому збірка також створює копію `index.html` для маршруту кожної мови та `404.html`.

### Як оновити прев'ю посилань

Месенджери кешують картку, яку збудували для посилання, і ще довго показують стару, хоча сам сайт уже змінився. Найупертіший тут Telegram, і кешує він за точним рядком URL, тож корінь і кожен мовний маршрут — окремі записи. Після розгортання, яке зачепило `index.html`, `scripts/shareMeta.ts` чи картинки `og-*.jpg`, оновіть кожну адресу, яку ви справді надсилаєте людям, — корінь сайту, `/ua`, `/ru` та `/en`:

| Платформа | Інструмент                                                                         | Примітка                                               |
| --------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| WhatsApp  | [Sharing Debugger](https://developers.facebook.com/tools/debug/), **Scrape Again** | Робіть першим: він же чистить кеш, який читає WhatsApp |
| Telegram  | надішліть посилання боту [@WebpageBot](https://t.me/WebpageBot)                    | Єдиний спосіб; згодуйте йому кожну адресу окремо       |
| LinkedIn  | [Post Inspector](https://www.linkedin.com/post-inspector/)                         | Пересканує на кожен запит                              |
| X         | вставте у вікно створення допису, подивіться, чернетку викиньте                    | Валідатор карток закрили 2022 року                     |

Telegram будує прев'ю і в «Збережених», а це найтихіше місце, щоб перевірити результат.
